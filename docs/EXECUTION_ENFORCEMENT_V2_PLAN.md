# Company OS Execution Enforcement V2

This plan converts reality-first execution from manager guidance into controller-enforced behavior.

## Invariants

1. Reversible product execution begins immediately and may run concurrently with bounded discovery.
2. Candidate one is governed by a First Reality Contract, not the full final product scope.
3. Every dispatch is authorized by a current Executive Governor decision.
4. Paused work classes cannot be dispatched or continued.
5. Capability state advances only from artifact and runtime evidence.
6. Missing execution deadlines trigger intervention, worker replacement, then manager replacement.
7. Research and documentation after bootstrap require a named consumer and active blocker.
8. Supplied repositories, providers, SDKs, and frameworks must be exercised before replacement is authorized.
9. Accepted product bytes are checkpointed before governance metadata can close a lane.
10. Scheduler wakes are leased, generation-bound, and expire with the mission.

## Delivery sequence

1. Stabilize CI and remove self-modifying patch workflows.
2. Add mission execution state, budgets, deadlines, work accounting, and scheduler leases.
3. Derive and persist a First Reality Contract alongside the final outcome stack.
4. Start a reversible reality spike concurrently with discovery.
5. Run the Executive Governor at every director transition and dispatch boundary.
6. Compile only governor-authorized work classes and the current global bottleneck.
7. Require artifact and runtime receipts to advance capabilities and deadlines.
8. Add automatic checkpoint requests, manager performance records, and replacement orders.
9. Reduce evaluator calibration through reuse, targeted dimensions, and a strict remaining-budget ceiling.
10. Prove behavior with website, n8n, Firecrawl, and support-slice regression missions.

The original outcome remains the authority. Governance exists to accelerate and verify execution, not to replace it.
