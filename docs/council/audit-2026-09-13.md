# Board and model audit — 2026-09-13

## Scope

Audit the Company OS orchestration framework's native conversation hierarchy and
Council OS deliberation. Company OS Web is business context storage/display. The
live decision is a fictional arithmetic/strategy fixture, not authenticated business
context or a test of business efficacy.

## Defects corrected

- Reversed bootstrap: the previous role told an executive to create a projectless
  board. The entry conversation now establishes the board in the instance's host
  project; the board appoints executive conversations, which create management
  conversations and Luna worker teams in that same project.
- Executive bypass: the old coordinator's primary-thread-to-manager instruction
  now applies to each board-appointed executive's portfolio.
- Consultation collision: each decision has its own session binding and decision
  ID, so concurrent executive consultations do not overwrite one shared session.
- Conversation topology: the exported organization checker rejects duplicate or
  pending IDs, foreign instance/project bindings, wrong parent roles, missing
  message/acknowledgement references, and incorrect manager model/reasoning intent.
  References must still be checked against actual host outputs.
- Council records could reuse one runtime reference for every seat. Council now
  requires distinct member references in each stage and rejects malformed/nonfinite
  inputs. A valid record still requires 17 recommendations, 17 complete peer
  rankings, a memo, and exact request/roster binding.
- Sol was hardcoded beyond prose: manager templates, compilers, validators and
  provider requests now select gpt-6-astra with medium reasoning. Luna workers
  remain gpt-5.6-luna. Historical evidence is preserved, not relabeled as Astra.

## Execution boundary

Each board-appointed executive is the master of an existing executive → manager →
worker subtree. Multiple executives and multiple managers are supported. Arbitrary
manager-under-manager recursion is not supported by the current native execution
contract. Board deliberation uses distinct temporary member agents; executive,
manager and worker roles require persistent host-native project conversations.

The host agent performs actual native tool calls. Python validators check exported
artifacts and do not themselves create chats or enable background runtime adapters.
Requested model settings are kept separate from independently observed model identity.
