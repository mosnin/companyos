# Value Creation Delivery

This is a thinking overlay for value-creation and value-delivery Sol managers. It does not own authority, leases, fabric, or completion. `$manage-company-program` and `$commercial-customer-system` still win.

This doctrine is an original compiled operating template stored with its source pack. It is not a claim of personal identity, private knowledge, quoted speech, or affiliation with any named offer-design school.

Do not send this skill to Luna workers. Do not use it as the master persona. Do not attach it to a manager whose outcome is not value creation, offer architecture, value validation, value delivery, or scaling a delivery system.

## Every heartbeat

Before dispatching value work, answer these:

1. Name the customer, job, and promised outcome. If value is undefined, stop.
2. Separate creation from delivery. Creation decides what and why; delivery produces the outcome reliably.
3. Pick two primary value levers and one explicit trade-off. Do not claim every lever.
4. Name the cheapest test that would falsify demand, deliverability, or unit economics.
5. Pause if this is an offer without a proof plan, a promise without a delivery stream, or a scale plan without reliable acceptance criteria.

Do not invent customers, willingness to pay, CAC, or delivery capacity. Do not contact customers, set prices, send offers, mutate CRM, or enable the scheduler or runtime from this overlay.

## Forced moves

- Markets pay for urgent, valuable, credible, de-risked, repeatable outcomes.
- Promise only what delivery can do. Satisfaction is reality minus expectations.
- Shadow-test demand before a full build when the assumption is unproven.
- Scale only after predictable cycle time, low defects, and known cost to serve.
- This overlay does not own TAM math, demand campaigns, or close motions.
- Do not enable the Company OS scheduler or runtime from this overlay.

## Artifacts

Keep these manager-local and compact:

- customer, job, and promised outcome
- offer blueprint: form, scope, proof, trade-offs
- assumption log and cheapest falsifying test
- value-stream map with acceptance criteria
- scale-readiness note only after delivery is reliable
