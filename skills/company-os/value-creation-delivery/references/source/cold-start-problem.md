## CS00: Use note and operating premise

This guide turns the photographed contents of The Cold Start Problem into a linear operating manual for building, launching, scaling, defending, and diagnosing products that depend on network effects. It is not a replacement for the book. It is an applied systems guide meant for founders, product leaders, growth operators, investors, and LLM agents that need to navigate the domain quickly.

Search any section code such as CS12 or CS41 to jump directly to that layer of the model. The codes are stable anchors for human review, LLM retrieval, and future notes.

Core premise: a networked product is not merely a product with users. It is a system where user value, adoption, engagement, economics, and defensibility are shaped by the presence, behavior, density, trust, and participation of other users.

## CS01: One page executive model

The advanced model has seven layers.

Layer 1: Define the network. Name the nodes, the edges, the interaction type, the value created by each interaction, and the minimum group size required for value to appear.

Layer 2: Find the atomic network. Identify the smallest group that can deliver a complete use case without relying on the full global network.

Layer 3: Solve the cold start. Concentrate supply, demand, content, trust, context, and timing into a narrow launch wedge until users can reliably experience value.

Layer 4: Cross the tipping point. When retention, referrals, usage density, and perceived usefulness begin reinforcing each other, shift from manual orchestration to repeatable growth.

Layer 5: Create escape velocity. Strengthen acquisition, engagement, and economics until growth is not just larger, but cheaper, more durable, and more self reinforcing.

Layer 6: Manage the ceiling. As networks grow, they develop congestion, spam, quality decay, incentive conflict, audience fatigue, and declining marginal returns. Treat ceilings as system design problems, not merely growth problems.

Layer 7: Build the moat. A network moat exists when the best users, data, behavior, integrations, workflows, reputation, liquidity, and institutional trust compound inside your product faster than competitors can copy them.

The operating rule: never scale a broken atomic network. Scaling a weak network magnifies its weak side, its abuse vectors, and its cost structure.

## CS02: Network effect primitives

A network effect exists when the value of a product rises because more relevant participants use it. The key word is relevant. More total users do not automatically create more value. A million inactive or mismatched participants can be less useful than one hundred well matched participants.

Primitive 1: nodes. These are users, buyers, sellers, creators, viewers, drivers, riders, merchants, developers, publishers, advertisers, employees, or any other actor class.

Primitive 2: edges. These are relationships or interactions between nodes. They include messages, transactions, follows, meetings, recommendations, bookings, reviews, payments, shares, comments, matches, and workflow handoffs.

Primitive 3: density. Density measures how many useful edges exist inside a defined network. Density matters more than raw user count because utility usually comes from finding the right person, item, or response at the right time.

Primitive 4: liquidity. Liquidity means the network can satisfy a user need with acceptable speed, quality, reliability, and price. A marketplace is liquid when buyers find acceptable supply and sellers find acceptable demand.

Primitive 5: trust. Trust lets users interact without excessive search, fear, or verification cost. Reputation, reviews, identity, guarantees, moderation, and dispute resolution convert strangers into counterparties.

Primitive 6: feedback. A healthy network feeds back into itself. Usage creates data. Data improves matching. Better matching increases utility. Higher utility improves retention and referral. Retention and referral grow the network.

Primitive 7: asymmetry. Networks usually have a hard side. One class of users is harder to acquire, harder to retain, or more essential to value creation. Strategy begins with the hard side.

## CS03: Network type taxonomy

Direct network effects: every additional relevant user increases value for other users in the same class. Examples include communication networks and social products.

Indirect network effects: one class of users increases value for another class. Marketplaces, payment networks, developer ecosystems, and creator platforms often work this way.

Data network effects: usage improves the dataset, which improves the product, which attracts more usage. This can matter in recommendation, matching, fraud detection, routing, personalization, and search.

Social network effects: value comes from identity, reputation, belonging, influence, and social graph density.

Market network effects: value comes from a blend of transactions, relationships, workflow, identity, and data. These are common in professional services, hiring, finance, logistics, health care, and industry specific software.

Protocol and standard effects: value grows when a standard becomes easier to adopt than to avoid. Examples include file formats, APIs, payment rails, identity protocols, and messaging standards.

Physical network effects: infrastructure density improves service quality. Delivery, mobility, payments, logistics, and local service networks often require physical or geographic density.

The taxonomy matters because each type has a different cold start path. A social product needs identity and graph density. A marketplace needs liquidity. A developer platform needs tools, docs, APIs, use cases, and early distribution. A data product needs enough signal to improve output quality.

## CS04: Measurement model for network strength

A network effect is only real if it shows up in behavior. Measure it through the user experience, not through vanity growth.

Primary signal: retention rises as network density rises. If users in denser cohorts retain better than users in sparse cohorts, the network may be creating durable utility.

Second signal: activation depends on network presence. If new users activate better when they find friends, supply, content, peers, counterparties, or integrations, the network is influencing onboarding.

Third signal: usage frequency increases with useful connections. More relevant edges should produce more sessions, messages, bookings, trades, payments, posts, comments, shares, or workflow events.

Fourth signal: acquisition cost falls with network maturity. Strong networks attract users through referrals, invitations, word of mouth, embedded sharing, marketplace demand, and reputation.

Fifth signal: pricing power improves with utility. If users pay more, switch less, or expand usage as the network grows, the network is strengthening economics.

Sixth signal: competitive win rate improves inside dense clusters. If a competitor cannot pry users away from a dense local, social, or workflow network, you are approaching moat territory.

Useful metric families: activation rate, time to first value, connection density, match rate, fill rate, reply rate, transaction success, repeat interaction, cohort retention, invite rate, referral conversion, marginal acquisition cost, contribution margin, abuse rate, trust incidents, supply quality, and user concentration.

## CS05: Cold Start Theory as a lifecycle

The lifecycle can be expressed as five stages.

Stage 1: cold start. The product has little or no network value because the right participants are not present at the same time, in the same context, with enough density.

Stage 2: tipping point. Local network utility begins to compound. New users can experience value without heroic manual intervention. The product starts to feel alive.

Stage 3: escape velocity. Growth compounds through acquisition, engagement, and economics. The network becomes easier to grow because the existing network makes the next user more likely to join and stay.

Stage 4: ceiling. Growth slows because the best wedges are saturated, quality decays, marginal users are less valuable, acquisition channels degrade, or the network creates negative externalities.

Stage 5: moat. The network becomes defensible through density, behavior, data, trust, brand, workflow integration, switching cost, reputation, supply depth, demand depth, and institutional learning.

The lifecycle is not strictly linear. A company can have escape velocity in one city and cold start in another. It can have a moat in one segment and a ceiling in another. Always diagnose by network, not by company average.

## CS06: Atomic network design

An atomic network is the smallest stable unit that can deliver the core network value. It is the primitive unit of expansion.

For a social product, the atomic network might be a friend group, class, team, club, neighborhood, or creator community.

For a marketplace, it might be one geography, one inventory category, one buyer segment, one seller segment, one price band, or one urgent job type.

For a collaboration tool, it might be a team, department, workflow, project, or partner relationship.

For a payments product, it might be one merchant cluster, one buyer behavior, one platform integration, or one recurring transaction pattern.

A good atomic network has four properties.

Property 1: users can complete the core use case inside it.

Property 2: members have a reason to interact with one another repeatedly.

Property 3: the success criteria are measurable in days or weeks, not years.

Property 4: the network can be replicated into adjacent atomic networks after proof.

The atomic network question is: what is the smallest group that can make the product feel complete?

## CS07: The hard side and the scarce side

The hard side is the participant class that constrains the network. It may be supply, demand, creators, experts, hosts, drivers, contributors, developers, community leaders, employers, merchants, moderators, or institutional partners.

The scarce side is not always the side with fewer total users. It is the side whose absence destroys value. A marketplace without qualified sellers fails. A community without high quality contributors fails. A developer platform without useful tools and docs fails. A social product without the relevant people fails.

Hard side strategy has five steps.

Step 1: identify the constraint. Which participant class has the highest acquisition difficulty, activation friction, trust burden, quality variance, or retention risk?

Step 2: define their success. What job are they hiring the network to do? Revenue, status, convenience, distribution, data, workflow, identity, or belonging?

Step 3: reduce their cost. Remove onboarding, uncertainty, switching, training, workflow, reputation, and liquidity friction.

Step 4: create privileged value. Give the hard side a reason to join before the easy side is abundant.

Step 5: protect them. Prevent spam, low quality demand, reputation harm, bad incentives, and platform extraction from degrading their experience.

## CS08: Anti network effects and failure loops

Not all growth improves a network. Anti network effects appear when more users reduce value.

Common anti network effects include congestion, spam, harassment, fraud, fake reviews, low quality content, over supply, under supply, low intent demand, price compression, status dilution, notification overload, support overload, and regulatory scrutiny.

Failure loop 1: more users create lower quality interactions. Lower quality interactions reduce retention. Lower retention creates a need for more acquisition. More acquisition adds more low intent users. The loop accelerates decline.

Failure loop 2: the easy side overwhelms the hard side. Buyers flood a marketplace but sellers do not respond. Viewers flood a creator platform but creators do not monetize. Recruiters flood a talent platform but talent churns.

Failure loop 3: growth incentives reward the wrong behavior. Users optimize for visibility, referral credits, vanity engagement, or arbitrage instead of true value creation.

Failure loop 4: local density is replaced with global averages. The company reports growth, but individual users experience sparse, irrelevant, or noisy networks.

Defense begins with design constraints: rate limits, reputation systems, quality bars, onboarding gates, trust signals, moderation, payment risk controls, eligibility, segmentation, and feedback instrumentation.

## CS09: Magic moments and minimum viable density

A magic moment is the first experience where the user understands why the network matters. It is not a marketing message. It is a felt proof.

Examples of magic moment categories include finding someone you know, getting a fast reply, completing a first transaction, receiving useful content, solving a painful workflow, earning status, getting paid, feeling recognized, discovering rare supply, or seeing a recommendation that feels unusually relevant.

Minimum viable density is the level of network completeness required for that moment to occur reliably. For some products it requires two people. For others it requires hundreds of listings, dozens of creators, thousands of searchable records, or trusted institutional partners.

Design question: what must be true in the first session, first day, first week, and first month for the user to believe this network is worth returning to?

Execution pattern: make the first magic moment manually reliable before trying to automate it. Concierge onboarding, seeded content, curated supply, guided invitations, community rituals, office hours, and direct outreach can all be valid if they create the proof needed to learn.

## CS10: Product sequence and launch constraints

Networked products require sequence discipline. The correct product for a large network may be the wrong product for a cold network.

Early sequence: narrow use case, small group, manual orchestration, high trust, clear value, low friction, measurable activation.

Middle sequence: repeatable atomic network playbook, user invitations, referral paths, integration, content growth, workflow embed, and early monetization tests.

Late sequence: broad discovery, personalization, algorithmic ranking, marketplace balancing, advanced monetization, moderation tooling, internationalization, and platform governance.

The common mistake is building late stage features before the first atomic network is stable. Ranking, feeds, complex search, global recommendations, monetization, and automation are often weak when there is no density, no signal, and no repeatable behavior.

Launch constraint: the first user experience must not depend on a future network that does not exist yet. Either seed the network, shrink the network, provide single player utility, or create a tool that creates the network as a byproduct.

## CS11: Stage one: create the first stable network

Objective: make one atomic network work with enough density that users experience real value.

Input constraints: few users, low trust, limited content, weak reputation, high manual effort, uncertain messaging, and fragile retention.

Execution sequence:

1. Choose a wedge where the need is intense, not broad.

2. Define the atomic network boundary. It might be one team, one city, one niche, one workflow, one group, one event, one creator category, or one high urgency transaction.

3. Identify the hard side and recruit it first.

4. Seed enough supply, content, peers, data, or workflow artifacts for the network to feel alive.

5. Create a narrow magic moment and measure whether users reach it.

6. Use manual operations to compensate for missing network density.

7. Keep the network small enough to be coherent and dense.

8. Expand only after activation and retention prove that the network can sustain itself.

Leading indicators: high intent signups, repeat usage, first reply, first transaction, first collaboration, first saved item, first invite, first review, first payment, first return session.

## CS12: Stage two: reach the tipping point

Objective: make growth begin to compound inside a repeatable network unit.

A tipping point is reached when users no longer need to be convinced that the product might work. The network itself demonstrates value.

Signals of tipping point:

1. New users experience value faster as the network grows.

2. Invites convert because recipients recognize the context.

3. Retention improves in denser clusters.

4. Supply responds because demand is visible.

5. Demand returns because supply is reliable.

6. Organic acquisition appears through social proof, sharing, and word of mouth.

7. Manual operations decline per successful interaction.

Tipping point strategy is not to go broad. It is to replicate the winning atomic pattern. If one neighborhood, team, company, creator niche, or use case works, find the adjacent cluster where the same constraints and incentives hold.

## CS13: Stage three: create escape velocity

Objective: turn a working network into a compounding growth engine.

Escape velocity depends on three forces.

Force 1: acquisition effect. The existing network lowers the cost of acquiring the next user through invites, referrals, embedded sharing, social proof, distribution partnerships, content discovery, and viral workflows.

Force 2: engagement effect. The network increases user activity as more relevant participants, content, workflows, or counterparties appear.

Force 3: economic effect. The network improves monetization, willingness to pay, transaction volume, ad value, conversion, or unit economics.

The forces reinforce each other when the product converts usage into invitations, invitations into density, density into engagement, engagement into economics, and economics into more product investment.

Escape velocity requires guardrails. A product can grow quickly while weakening quality. Measure the ratio between scale and trust, not merely scale.

## CS14: Stage four: manage the ceiling

Objective: identify and remove the constraints that stop network growth from compounding.

Ceilings often appear after early success. The product still grows, but each additional user creates less marginal value. The network may have saturated the best segment, exhausted the best acquisition channel, overloaded the hard side, or created quality decay.

Common ceilings:

1. Segment ceiling. The initial niche is saturated.

2. Geographic ceiling. Local networks do not transfer cleanly.

3. Quality ceiling. More content or supply reduces average usefulness.

4. Trust ceiling. Fraud, abuse, or bad incentives grow faster than governance.

5. Channel ceiling. The best acquisition channels degrade.

6. Economic ceiling. Subsidies, incentives, or support costs overwhelm margin.

7. Product ceiling. The product cannot support adjacent use cases.

Ceiling strategy: diagnose the binding constraint, then change one of the following: segment, product, pricing, trust system, acquisition loop, ranking system, supply strategy, demand strategy, or governance model.

## CS15: Stage five: build the moat

Objective: convert network scale into defensibility.

A moat is not a user count. It is the accumulated difficulty of replacing the network. Strong network moats appear when users, data, reputation, integrations, standards, content, trust, and workflow all compound together.

Moat ingredients:

1. Dense graph. Users have many valuable relationships inside the product.

2. Embedded workflow. The product becomes part of regular operations.

3. Reputation capital. Users cannot easily move history, ratings, followers, status, or trust.

4. Data advantage. Usage improves matching, personalization, safety, routing, pricing, or discovery.

5. Supply depth. The network has more or better inventory, content, experts, creators, or counterparties.

6. Demand depth. Participants know that the product is where the audience, buyers, peers, or opportunities are.

7. Institutional trust. Partners, regulators, customers, and developers depend on the network.

8. Learning curve. The organization has operational knowledge competitors cannot quickly copy.

The strongest moat is a virtuous cycle that competitors cannot interrupt without paying more, moving faster, or offering radically better value.

## CS16: Part One guide: network effects

Part One sets the mental model. The key advanced move is to stop treating network effects as a label and start treating them as a system variable.

For each product, answer:

1. Who are the participants?

2. What value does each participant create for others?

3. What must be true for that value to be visible?

4. Which network type is present?

5. What is the minimum density needed?

6. What makes the network stronger with scale?

7. What makes it weaker with scale?

8. What can competitors copy, and what cannot be copied without the same network?

The goal of Part One is not inspiration. It is precision. Define the network before building the growth system.

## CS17: Part Two guide: the cold start problem

Part Two focuses on getting the first network unit to work.

Advanced principle: most early network products fail because they try to build a global network before proving a local network.

Use this sequence:

1. Shrink the market until density is achievable.

2. Recruit the hard side with a tailored value proposition.

3. Seed the missing side manually if necessary.

4. Design the magic moment around one high value use case.

5. Measure whether users return because of the network, not because of novelty.

6. Protect the first users from low quality interactions.

7. Turn manual orchestration into a repeatable playbook.

Case pattern lessons from the contents: Tiny Speck implies pivots and emergent network behavior. Credit cards imply infrastructure and merchant adoption. Wikipedia implies contributor power. Tinder implies solving a high friction social problem. Zoom implies reliability as network enabler. Clubhouse implies the energy of live participation and social scarcity.

## CS18: Part Three guide: the tipping point

Part Three focuses on converting a working atomic network into repeatable expansion.

Advanced principle: the tipping point is not one global moment. It is a repeatable local pattern. Tinder, LinkedIn, Instagram, coupons, Reddit, and Uber all represent different ways to create enough density for the network to begin pulling new participants in.

Tipping point mechanisms:

1. Invite only scarcity can create status and trust if the network is valuable before broad access.

2. Tool first utility can seed behavior before the network is complete.

3. Subsidies can accelerate density when they are time bounded and learning driven.

4. Flintstoning means manually performing what technology will later automate.

5. Hustle means doing unscalable work until the repeatable pattern is discovered.

6. Local dominance beats broad weakness.

Do not confuse press, downloads, waitlists, or launch excitement with tipping point. The true signal is repeat behavior and peer driven expansion.

## CS19: Part Four guide: escape velocity

Part Four explains how networks accelerate after local proof.

Escape velocity requires a compounding model, not a campaign model. Campaigns spend energy. Networks reuse energy.

Acquisition effect: build invitations, referrals, shared artifacts, embedded distribution, and social proof into the product experience. The best acquisition loops make inviting others part of completing the user job.

Engagement effect: increase the useful interactions available to each user. Better recommendations, more relevant peers, richer content, stronger notifications, deeper workflows, and better status systems can all raise engagement.

Economic effect: scale should improve revenue quality. This may happen through higher conversion, better targeting, richer transaction volume, more reliable supply, higher willingness to pay, or better risk selection.

The escape velocity dashboard should show that scale improves at least two of the three forces while not degrading quality or trust.

## CS20: Part Five guide: the ceiling

Part Five warns that network effects can weaken after growth.

A ceiling is the point where the previous playbook stops producing compounding returns. The product may still be large, but growth gets noisier, slower, or more expensive.

Ceiling sources mapped to the contents:

1. Twitch: creator and viewer dynamics can create concentration and discovery problems.

2. Rocketship growth and T2D3: rapid growth creates organization, infrastructure, and market expectations that can outrun product quality.

3. Saturation: the best markets or user segments can fill up.

4. Law of shitty clickthroughs: acquisition channels decay as novelty disappears and competition rises.

5. Network revolt: users, providers, creators, or sellers can push back when incentives feel unfair.

6. Eternal September: a flood of new users can overwhelm norms.

7. Overcrowding: more content, supply, or participants can reduce discoverability and trust.

Ceiling management requires segment level diagnosis. Ask where density is too low, where density is too high, where quality is decaying, and where incentives are misaligned.

## CS21: Part Six guide: the moat

Part Six explains how networks defend themselves.

A moat can arise from scale, but only if scale produces durable advantage. The strongest networks have a recursive advantage: they attract the best users because they already have the best users.

Moat mechanisms mapped to the contents:

1. Airbnb versus competitors: dense, trusted, distinctive inventory can be difficult to replicate city by city.

2. Vicious and virtuous cycles: small differences compound when every loop feeds the next.

3. Cherry picking: competitors may attack the best segments first, so incumbents need depth and segment defense.

4. Big bang failures: large companies can fail when they cannot reproduce the social, cultural, or behavioral density of a network.

5. Competing over the hard side: the side that constrains value often becomes the real battlefield.

6. Bundling: a large company can use adjacent products, distribution, or integrated workflows to attack a network.

Advanced moat question: what would a competitor have to reproduce at the same time to make your product feel replaceable?

## CS23: Diagnostic questions by stage

Cold start diagnosis:

1. What is the smallest network that can complete the core use case?

2. Which side is hard, scarce, or trust sensitive?

3. What must be seeded for the first users to experience value?

4. What is the first magic moment?

5. What manual work is needed to make that moment reliable?

6. What is the activation event that predicts retention?

Tipping point diagnosis:

1. Which atomic network has proved retention and repeat interaction?

2. Can the pattern repeat in adjacent clusters?

3. Are invites, referrals, shares, or embedded workflows emerging naturally?

4. Is the hard side responding faster as density grows?

5. Are users describing the product as a place where something happens, not just a tool?

Escape velocity diagnosis:

1. Does the network reduce acquisition cost?

2. Does the network raise engagement?

3. Does the network improve economics?

4. Are growth loops improving with scale or merely consuming budget?

5. Is quality stable as user count rises?

Ceiling diagnosis:

1. Which segment has stopped compounding?

2. Which channel has degraded?

3. Which user class is dissatisfied?

4. Where is density too low or too high?

5. Which incentives are creating abuse or low quality behavior?

Moat diagnosis:

1. What data, reputation, workflow, supply, trust, or distribution would a competitor need to copy?

2. Which user relationships are locked into the network?

3. Which behavior gets stronger the longer the network exists?

4. Can a competitor cherry pick the best users or segments?

5. What must be bundled, integrated, or defended?

## CS24: Metrics and dashboards

A network dashboard must separate global averages from local density.

Core dashboard families:

1. Activation: signup to first useful action, first reply, first transaction, first connection, first saved artifact, first invite.

2. Density: average useful connections per user, supply per demand unit, available inventory per geography, contributor count per topic, active peers per team.

3. Liquidity: match rate, fill rate, response time, transaction success, search success, booking success, inventory coverage, answer quality.

4. Retention: cohort retention by density bucket, hard side retention, power user retention, repeat transaction rate, repeat contribution rate.

5. Growth loops: invites sent, invite conversion, referral rate, share rate, viral cycle time, cost per acquired user, organic share of acquisition.

6. Engagement: session frequency, interaction frequency, messages, comments, transactions, content creation, workflow completion, usage depth.

7. Economics: revenue per active user, take rate, contribution margin, subsidy cost, payback period, expansion rate, churn, lifetime value.

8. Trust and quality: fraud rate, abuse reports, spam rate, moderation load, dispute rate, refund rate, complaint rate, ranking satisfaction.

9. Saturation: addressable segment penetration, channel cost trend, marginal retention trend, marginal user value, hard side capacity utilization.

The best dashboard answers one question: where does network density create value, and where does scale destroy value?

## CS25: Acquisition loop design

An acquisition loop is stronger than a campaign because usage generates new acquisition.

Loop types:

1. Invite loop. A user invites another user to complete the task.

2. Collaboration loop. The product is useful only when others participate in a shared workflow.

3. Content loop. A user creates content that attracts viewers, and viewers become users.

4. Marketplace loop. Demand attracts supply, supply attracts demand.

5. Referral loop. Users recommend the product because they gain value when others join.

6. Reputation loop. Public status or proof increases a participant's incentive to bring others.

7. Integration loop. The product travels through calendars, files, payments, messages, links, or APIs.

Design rules:

1. The invite should be necessary or natural, not decorative.

2. The recipient should understand why they were invited.

3. The first experience should be personalized by the inviter, context, object, or workflow.

4. The loop should create value before asking for promotion.

5. The loop should be measured by activated recipients, not sent invites.

## CS26: Engagement loop design

An engagement loop increases participation because the network becomes more useful over time.

Loop anatomy:

1. Trigger. A notification, need, social signal, workflow event, or content update brings the user back.

2. Action. The user interacts, posts, searches, books, replies, pays, collaborates, or contributes.

3. Network response. Other users or the system respond.

4. Reward. The user receives value, status, information, money, convenience, or belonging.

5. Investment. The user adds data, content, relationships, reputation, preferences, or workflow history.

6. Future utility. The investment makes the next session better.

Advanced design: create an engagement ladder. Move users from passive consumption to light interaction, then contribution, then creation, then leadership, then advocacy. Each rung should have a clear trigger, reward, and low friction next action.

Do not maximize activity blindly. Maximize useful activity. Empty comments, low quality likes, fake engagement, and notification addiction can inflate metrics while damaging the network.

## CS27: Economic loop design

The economic effect appears when scale improves monetization or cost structure.

Economic loop sources:

1. Better matching increases conversion.

2. More data improves risk selection.

3. More supply lowers search cost.

4. More demand increases seller utilization.

5. More trust lowers support and dispute cost.

6. More history increases switching cost.

7. More integrations increase expansion revenue.

8. More reputation enables premium pricing.

9. Better liquidity increases transaction frequency.

Economic metrics:

1. Contribution margin by atomic network.

2. Revenue per active participant by density bucket.

3. Subsidy required per successful interaction.

4. Payback period by acquisition source.

5. Hard side earnings, utilization, and retention.

6. Demand side repeat rate and willingness to pay.

7. Fraud, refunds, disputes, and support cost per transaction.

A network is economically strong when growth lowers marginal cost or raises marginal value. If growth requires ever larger subsidy per useful interaction, the network is not yet compounding economically.

## CS28: Market entry and sequencing

The market entry decision is the highest leverage strategic choice in cold start work.

Choose a wedge that has:

1. High pain.

2. Dense relationships or transactions.

3. Clear hard side value.

4. Measurable activation.

5. Low initial surface area.

6. Replicable adjacency.

7. Users who can reach each other.

8. A reason to act now.

Bad wedges are broad, diffuse, low urgency, hard to measure, fragmented, culturally incoherent, or dependent on partners who do not care.

Sequencing model:

1. Prove one atomic network.

2. Repeat the atomic pattern across adjacent networks.

3. Build tooling to reduce manual setup.

4. Connect adjacent networks when cross network value appears.

5. Add broader discovery and monetization only after density exists.

6. Expand to harder segments after the playbook can absorb variance.

## CS29: Incentives, subsidies, and bootstrapping

Incentives can accelerate density, but they can also hide weak product value.

Good incentives:

1. Reduce early risk for the hard side.

2. Accelerate first interactions.

3. Teach the market how the network works.

4. Are tied to true activation or contribution.

5. Decline as network utility grows.

Bad incentives:

1. Reward vanity actions.

2. Attract mercenary users.

3. Inflate supply without demand.

4. Create fake activity.

5. Create expectation of permanent subsidy.

6. Mask poor retention.

Use incentives as instruments for learning, not as replacements for network utility. Every incentive should have a hypothesis, success metric, stop rule, and abuse control.

## CS30: Community, trust, and moderation

Community is not decoration. It is governance for network quality.

Trust primitives:

1. Identity. Users know who they are dealing with.

2. Reputation. Past behavior informs future trust.

3. Rules. Participants know acceptable behavior.

4. Enforcement. Bad behavior has consequences.

5. Transparency. Users understand decisions.

6. Recovery. Mistakes and disputes have pathways.

7. Norms. The community has expected rituals, tone, and contribution standards.

Moderation must scale before abuse scales. The system should distinguish novice mistakes, low quality behavior, spam, fraud, harassment, and coordinated attacks. Each requires a different response.

In early networks, founders often act as culture setters. The first users teach the next users what the product is for. Choose them carefully.

## CS31: Competitive strategy

Network competition is rarely a pure feature comparison. It is a battle over density, trust, hard side participation, distribution, economics, and switching cost.

Attack surfaces:

1. Cherry picking high value segments.

2. Subsidizing the hard side.

3. Bundling with a larger platform.

4. Offering better economics to creators, sellers, or developers.

5. Building a superior single player tool.

6. Reducing friction in an overlooked use case.

7. Exploiting incumbent trust failures.

8. Focusing on a new geography, culture, or workflow.

Defense moves:

1. Increase hard side loyalty.

2. Improve economics for core participants.

3. Build better discovery and quality systems.

4. Deepen workflow integration.

5. Expand into adjacent atomic networks before challengers do.

6. Protect trust and user dignity.

7. Make switching expensive through genuine accumulated value, not coercion.

## CS32: Platform risk and policy constraints

Growth systems operate inside policy constraints. Compliance failures can destroy trust, distribution, and economics.

Marketing claims should be truthful, supported, and not misleading. Endorsements, testimonials, reviews, creator partnerships, and referral promotions need clear disclosure when there is a material connection.

Email, text, and notification loops should respect consent, opt out, message relevance, and jurisdictional rules. A viral loop that violates user trust may create short term growth and long term risk.

Search and content growth should avoid deceptive or manipulative behavior. Durable networks are built on useful content, not spam.

Data driven networks should respect privacy, security, data minimization, and user expectations. A data network effect becomes a liability if users feel exploited.

Platform dependency should be mapped. If acquisition relies on app stores, social graphs, search engines, ad networks, payment processors, or cloud providers, treat policy changes as strategic risk.

## CS33: Network quality, density, and liquidity

Network quality is the difference between a large network and a useful network.

Density questions:

1. Do users find relevant people, supply, content, or workflows quickly?

2. Is the network dense where users actually need it, or only in aggregate?

3. Are the best users available to new users?

4. Are high quality contributors being overwhelmed by low quality demand?

5. Is the ranking system creating winner take most dynamics that harm discovery?

Liquidity questions:

1. How often does a user need go unfulfilled?

2. How quickly does the network respond?

3. What is the minimum acceptable response time?

4. What percentage of interactions are successful?

5. What quality threshold must be met for users to return?

Quality controls include curation, ranking, filters, onboarding gates, trust signals, incentives, matching, quotas, reputation, community norms, expert review, and user education.

## CS34: Growth experiments and decision rules

Growth experiments should be tied to network hypotheses.

Bad experiment: increase signups.

Better experiment: increase activated users inside a target atomic network without lowering hard side retention.

Bad experiment: increase invite volume.

Better experiment: increase activated invite recipients who reach the magic moment within seven days.

Bad experiment: increase content volume.

Better experiment: increase content that receives useful engagement and improves retention.

Decision rules:

1. If activation rises but retention does not, the experiment may create shallow engagement.

2. If demand rises but hard side retention falls, the network is unbalanced.

3. If acquisition cost falls but abuse rises, the loop may be attracting wrong users.

4. If engagement rises but satisfaction falls, the product may be creating noise.

5. If monetization rises but trust falls, short term economics may be damaging the moat.

Every network experiment should include success metric, guardrail metric, segment, time window, expected mechanism, and decision threshold.

## CS43: LLM prompt pack

Prompt 1: Diagnose my network.
Use the framework in CS02 through CS15. Ask me for my product, user classes, core interaction, hard side, atomic network, first magic moment, and current metrics. Then classify the lifecycle stage and identify the binding constraint.

Prompt 2: Design an atomic network.
Use CS06 and CS37. Generate three possible atomic networks. For each, define participants, boundary, minimum viable density, hard side, magic moment, activation metric, manual operations, and expansion adjacency.

Prompt 3: Build a launch playbook.
Use CS11, CS29, and CS39. Create a thirty day plan for one atomic network with daily operating rituals, hard side outreach, demand seeding, trust controls, and scale criteria.

Prompt 4: Audit escape velocity.
Use CS13, CS24, CS25, CS26, CS27, and CS40. Determine whether acquisition, engagement, and economics are compounding or whether growth is campaign driven.

Prompt 5: Find the ceiling.
Use CS14, CS20, and CS41. Identify where growth is slowing, which metric proves it, which user class is affected, and what experiment should be run next.

Prompt 6: Stress test the moat.
Use CS15, CS21, CS31, and CS42. Simulate attacks by a focused startup, an incumbent platform, a subsidized competitor, and a bundler. Recommend defenses.

Prompt 7: Improve trust and moderation.
Use CS08, CS30, and CS33. Identify likely anti network effects, propose governance mechanisms, and define abuse metrics.

Prompt 8: Convert this into an investor memo.
Use CS01 through CS15. Present the network thesis, atomic network, hard side strategy, lifecycle stage, growth loops, economics, ceiling risks, and moat.
