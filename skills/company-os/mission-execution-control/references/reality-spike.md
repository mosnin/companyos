# Concurrent Reality Spike

For reversible local software missions, bootstrap creates two concurrent tracks.

## Reality spike

The reality spike inspects the repository, identifies the task archetype, makes the first product mutation, runs or renders the artifact, and records exact evidence. It uses provisional assumptions that are safe to revise.

## Focused discovery

Discovery researches only critical domain behavior, supplied implementations, dangerous assumptions, and quality references that affect the active spike.

Discovery does not block the first mutation or first runtime command unless it exposes a genuine safety, authority, or irreversible-effect issue. Findings update the spike through targeted repair rather than restarting the mission from documentation.
