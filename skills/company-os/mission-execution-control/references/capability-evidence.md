# Capability Evidence Transitions

Capability state is derived, never narrated.

1. `missing`: no bound evidence.
2. `partial`: exact product artifact bytes are materialized.
3. `runnable`: a bound runtime, browser, simulator, API, database, workflow, or gameplay receipt proves isolated execution.
4. `connected`: a First Reality journey receipt proves the capability participates in a complete user-observable path.
5. `verified`: an independent evaluator accepts the capability against current artifact and runtime evidence.

State changes are ordered and cannot skip a level. Evidence paths and digests remain bound to the transition. The global bottleneck is the earliest unresolved critical capability in the active journey, not the capability with the most documentation.
