# Outcome Control Plane Implementation

Status: source implementation complete for the first integrated outcome-control pass.

The Company OS source now contains an explicit control plane between a broad user objective and high-concurrency production execution.

## Control sequence

1. `$compile-outcome-contract` accepts a broad objective and turns unknowns into discovery blockers rather than requiring the operator to pre-author acceptance criteria.
2. `$close-outcome-discovery` closes unknowns only with cited evidence and preserves counterevidence.
3. `$define-outcome-artifacts` models interactive, visual, audio, executable, service, database, model, physical, and composite artifacts as first-class outcome objects. Rich artifacts cannot pass on file existence or nonempty text alone.
4. `$compile-outcome-evaluators` requires executable independent evaluator adapters. Research-only methods and production self-review cannot satisfy required quality proof.
5. `$compile-outcome-benchmarks` binds provenance-backed quality references and requires multiple quality tiers for evaluator discrimination.
6. `$calibrate-outcome-evaluator` requires an evaluator to rank materially different sealed candidates in the expected order before production scale.
7. `$authorize-outcome-scale` joins the outcome, artifact, evaluator, benchmark, and calibration contracts into one content-bound scale authorization.
8. `$compile-federated-company-kernel` now treats mandatory requirements and acceptance checks as compiled results of outcome understanding rather than knowledge the user must supply before autonomy begins.
9. `$operate-federated-codex-runtime` routes production scale through `prepare_authorized_native_codex_dispatch.py`, which rejects missing, blocked, stale, tampered, or objective-mismatched outcome authorization before native manager creation.
10. `$accept-outcome-reality` makes final acceptance from the original objective, actual artifact evidence, and independent evaluator receipts. Production completion narratives are inadmissible as final acceptance evidence.

## Authority model

Discovery may research only explicit outcome unknowns. Pilot work may build bounded candidates needed for observation or calibration. Ordinary production fanout requires a current outcome-scale authorization. Final release requires a separate reality-acceptance receipt.

No task creation, manager completion, process audit, kernel receipt, or scale authorization by itself proves that the resulting product is good.
