# Operator Command Center Acceptance Matrix

| Gate | Adversarial case | Required result |
| --- | --- | --- |
| Authority | SQLite exists while JSON export is tampered | Brief uses SQLite and truthfully marks export drift |
| Read-only behavior | Healthy or blocked brief rendering | No revision, event, lease, evidence, or work mutation |
| Redaction | State contains signed grants, nonces, and provider records | Projection exposes none of the protected fields or tokens |
| Markup safety | Project name/outcome contains HTML, links, controls, or newlines | Markdown renders inert one-line content |
| One next move | Control, evidence, quality, authority, and execution blockers coexist | Deterministic priority yields one action, never a list of competing work |
| Quality truth | Missing, below-gate, passing, critical, and noncritical scores | Exact score, threshold, state, and count are shown |
| Project direction | North star, outcome, metric, phase, and primary work | All appear without loading raw state |
| Supervision | No managers; several managers/reports; runtime attempts | Counts and safe identity fields are accurate; activity is not called progress |
| Feedback economy | Missing, invalid, and valid usage values | Safe finite totals; unknown never becomes a success claim |
| Governed change | Compare the current revision with the preceding or explicitly selected revision | Program, outcome, phase, work, evidence, status, and feedback changes are concise and attributable |
| Comparison scope | Default previous-revision comparison and explicit wider comparison | Exact `Update A → B` window is visible; counts say “in this comparison” and never imply total history |
| Invalid comparison | Requested revision is missing, current, future, zero, or corrupt | Command fails closed without changing state |
| Quality contract | Numeric score is above threshold but its grant, binding, artifact, or cited evidence is invalid | Row is `invalid`, never `pass`; exact issue remains visible in blockers |
| Blocker routing | Control, authority, evidence, program, quality, execution, cancellation, and ready states | Each state yields one explicit action with owner, output, done condition, and verification |
| Stage accessibility | Every phase state | Full named stage and state are present; meaning never depends on color or glyph alone |
| Desktop visual surface | 1435 × 1096 viewport | Current decision, four recent attributable changes, seven named stages, and the start of quality/work/team truth appear without horizontal overflow |
| Mobile visual surface | 375 × 812 viewport | Current decision is first visually, every disclosure target is at least 44 px high, and no horizontal overflow occurs |
| Disclosure interaction | Governed decision handoff, full trail, quality, manager, run, blocker, trust, evidence, and compass rows | Each native disclosure is keyboard-operable; summary truth and complete detail remain available without JavaScript |
| Semantic status | Ready, blocked, cancelled; certification current/not current; schedule safely off/ready on/invalid on | Color classes derive from truth; protected-off is neutral, accepted states are positive, and failures alone are coral |
| Decision affordance | Focal decision at every stage | Stage number is a noninteractive marker; a named link drills into the open governed handoff rather than implying an unsupported execute action |
| Motion accessibility | User prefers reduced motion | Entrance and current-stage pulse are disabled |
| Quality compression | Most or all dimensions pass | Passing rows collapse; only exceptions consume the decision surface |
| Manager accountability | Manager pending, reporting, awaiting decision, in rework, accepted, paused, or terminated | Phase, state, requested/observed model evidence, budget exception, and required decision are visible |
| Runtime accountability | Attempt requested but unobserved; provider-observed; invalid budget | Requested and observed identity remain distinct and budget evidence/exception is explicit |
| Historical continuity | Superseded evidence is archived by a later program replacement | Linear review history remains valid and the new program starts with no inherited proof |
| Issuer rotation | Historical grant has retained public key; legacy accepted grant lacks it | New history is cryptographically replayable; legacy limitation is warned, not misrepresented or made a current authority |
| Blocked monitor | `--strict` against a blocked project | Full brief prints and process exits nonzero |
| Default check-in | Blocked project without `--strict` | Full brief prints successfully so the user can inspect it |
| Empty project | No active work, evidence, managers, cycles, or quality | Coherent empty states and one reality-evidence action |
| Determinism | Same authoritative revision and environment | Same JSON/Markdown projection |
| Regression | Controller, store, observation, reference, distribution, compile | All accepted suites remain green |

## Quality target

The experience phase requires all 13 applicable critical dimensions at 9/10:
north-star alignment, user value, product coherence, differentiation,
innovation, domain fit, information architecture, usability, accessibility,
interaction quality, visual quality, brand cohesion, and evidence integrity.
An independent reviewer must score the rendered journey, not this specification.
